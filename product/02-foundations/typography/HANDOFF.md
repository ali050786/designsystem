# Typography · developer handoff

How to take ds typography from Figma into code and keep it correct. Read the [guide](GUIDE.md) first if you haven't — this
page assumes you know what styles, roles and breakpoints are. A working page that uses everything below is in
[demo/](demo/index.html); it has switches for 200% text and the WCAG text-spacing override, so you can see the styles survive both.

---

## What you get

All generated by the engine (`npm run build` → `engine/out/<name>/`). Never edit them by hand.

| File | What it is | Who uses it |
|---|---|---|
| `tokens.css` | Every style as CSS variables, switched by media queries, a `.ds-type-*` class per style, and base-layer defaults for `body`, headings, form controls, code and table numbers | Every web project |
| `tailwind.theme.css` | `text-<style>` utilities (size, line height, letter-spacing, weight) and `font-sans` / `font-mono` mapped to the family tokens | Tailwind projects |
| `tokens.json` | All tokens in the W3C design-token format; other breakpoints in `$extensions` | Other platforms, Style Dictionary |
| `figma/Responsive.<sm|md|lg|xl>.tokens.json` | The style (and layout) variables per breakpoint, for Figma | Design |
| `ai/rules/typography.md`, `ai/typography.contract.json` | The typography rulebook and contract for AI tools and the type checker | AI tools, the type checker |
| `report.html`, `report.json` | Every typography check, per style and breakpoint | Reviews, audits |

## Install

The same `tokens.css` as colour — nothing extra to load.

```html
<link rel="stylesheet" href="/css/tokens.css">
<link rel="stylesheet" href="/css/app.css">
```

Tailwind v4, in your main CSS file:

```css
@import "tailwindcss";
@import "./tokens.css";
@import "./tailwind.theme.css";
```

**Load the fonts yourself.** `tokens.css` names the families; your product serves the files. Use `font-display: swap` so
text shows straight away in the next font of the stack, and preload the two weights almost every page uses:

```html
<link rel="preload" href="/fonts/Inter-Regular.woff2" as="font" type="font/woff2" crossorigin>
<link rel="preload" href="/fonts/Inter-SemiBold.woff2" as="font" type="font/woff2" crossorigin>
```

```css
@font-face { font-family: Inter; src: url(/fonts/Inter-Regular.woff2) format("woff2"); font-weight: 400; font-display: swap; }
@font-face { font-family: Inter; src: url(/fonts/Inter-Medium.woff2) format("woff2"); font-weight: 500; font-display: swap; }
@font-face { font-family: Inter; src: url(/fonts/Inter-SemiBold.woff2) format("woff2"); font-weight: 600; font-display: swap; }
@font-face { font-family: Inter; src: url(/fonts/Inter-Bold.woff2) format("woff2"); font-weight: 700; font-display: swap; }
```

The mono family (JetBrains Mono) is only needed on pages that show code.

## What tokens.css already does

These are defaults in the `base` layer, so any class or utility you add still wins:

| Element | Gets |
|---|---|
| `body` | `type.body.md`, and long words break instead of forcing sideways scrolling |
| `h1` · `h2` · `h3` | `type.heading.lg` · `type.heading.md` · `type.heading.sm` |
| `h4` · `h5`, `h6` | `type.title.lg` · `type.title.md` |
| `code`, `kbd`, `samp`, `pre` | the mono family |
| `strong`, `b` | semibold (600), the system's emphasis weight |
| `button`, `input`, `select`, `textarea` | the page's font (browsers otherwise shrink them to about 13px) |
| `td`, `th`, `output`, `data` | tabular numerals |

So a plain HTML page already reads well; you add classes where the default isn't the right job.

## Breakpoints

Sizes switch with media queries at 600, 1024 and 1440px — there is no attribute to set. Only display and heading styles
change; everything else keeps one size. In Figma, the same switch is the frame's **Responsive** mode (sm, md, lg, xl).

## Names: Figma → CSS → Tailwind

Take the Figma text style name, replace `/` with `-`, and prefix it.

| Figma text style | CSS class | CSS variables | Tailwind |
|---|---|---|---|
| `type/body/md` | `.ds-type-body-md` | `--ds-type-body-md-font-size` (and `-line-height`, `-letter-spacing`, `-font-weight`, `-font-family`) | `text-body-md` |
| `type/heading/lg` | `.ds-type-heading-lg` | `--ds-type-heading-lg-…` | `text-heading-lg` |
| `type/code/md` | `.ds-type-code-md` | `--ds-type-code-md-…` | `text-code-md font-mono` |
| `type/numeric/md` | `.ds-type-numeric-md` | `--ds-type-numeric-md-…` | `text-numeric-md tabular-nums` |

The class sets everything a style holds. Tailwind's `text-*` utility sets size, line height, letter-spacing and weight —
add `font-mono` for code styles and `tabular-nums` for number styles (the type checker reminds you). Never use Tailwind's
own `text-sm`, `leading-*` or `tracking-*`: they bypass the styles and their checks.

When a component needs the values in its own rule, use all five variables together, never one of them:

```css
.toast-title {
  font-family: var(--ds-type-title-md-font-family); font-size: var(--ds-type-title-md-font-size);
  font-weight: var(--ds-type-title-md-font-weight); line-height: var(--ds-type-title-md-line-height);
  letter-spacing: var(--ds-type-title-md-letter-spacing);
}
```

## Patterns

Each pattern is in the [demo](demo/index.html), working at every width and with both reader settings.

### Headings follow the outline

```html
<h1>Settings</h1>                                   <!-- heading.lg by default -->
<h2>Notifications</h2>                              <!-- heading.md -->
<section class="card">
  <h3 class="ds-type-title-md">Email</h3>           <!-- a card: tag h3, style title.md -->
  <span class="ds-type-label-md">Weekly summary</span>  <!-- not a heading at all -->
</section>
```

Pick the tag from the outline (never skip a level) and the class from how much it should stand out. One display style per view.

### Paragraphs and line length

```css
.article { max-width: var(--ds-layout-measure-reading); }  /* 34rem — about 70 characters, grows with the text size */
.article p + p { margin-top: var(--ds-space-stack-lg); }   /* one line of body.md apart (Spacing foundation) */
```

Left-align running text; never justify it. Inline code goes one step down: `code.md` in `body.md`, `code.sm` in `body.sm` and captions.

### Labels, help and errors

```html
<label for="name" class="ds-type-label-md">Project name</label>
<input id="name" class="ds-type-body-md" aria-describedby="name-help">
<span id="name-help" class="ds-type-caption-md">Up to 60 characters.</span>
```

Errors use `caption.md` in `color.fg.danger`, with an icon and words, connected with `aria-describedby`. Placeholders are not labels.

### Numbers

Table cells already get tabular numerals. Right-align numeric columns, keep the decimals the same, put the unit in the
header and use a real minus sign (−). Outside tables, use a number style:

```html
<div class="metric">
  <span class="ds-type-label-md">Active users</span>
  <span class="ds-type-numeric-lg">12,480</span>
  <span class="ds-type-caption-md change-good">▲ 2.4% this week</span>
</div>
```

Values that update live (timers, counters, prices) need tabular numerals too, or they jitter as digits change.

### Long text: wrap first, truncate last

Let titles and labels wrap. Never give a text box a fixed `height` with `overflow: hidden` — at 200% text, or with the
reader's spacing override, the text is cut off. Use `min-height` if a box must be at least a certain size.

If you must truncate (a table cell, a breadcrumb), keep the full text available:

```html
<td><span class="cell-name" title="Customer onboarding flow for the enterprise plan">Customer onboarding flow for the enterprise plan</span></td>
```

```css
.cell-name { display: block; overflow: hidden; text-overflow: ellipsis; white-space: nowrap; } /* the type checker reminds you to keep the full text available */
```

`title` alone isn't reachable by keyboard; for anything people need, also offer an expand control or a details view.

### Emphasis

`<strong>` (semibold, set by tokens.css) and `<em>`. Underline only for links; never colour alone; no all-caps sentences.
If you need capitals for a short label, add a caps style in the config (see below) — it comes with the right letter-spacing.

### Zoom and text size

Never block zoom:

```html
<meta name="viewport" content="width=device-width, initial-scale=1">  <!-- no user-scalable=no, no maximum-scale -->
```

Size anything that holds text in `rem` or `em`, not `px`, so it grows with the reader's text size.

## Moving an existing product to ds type

Do it screen by screen — a style is chosen by its job, which you can only see on the screen.

1. **Find what's there.** `npm run lint:type -- path/to/your-app/src` lists every hand-set size, line height, letter-spacing and font family, with line numbers.
2. **Pick styles by job, not by nearest size.** For each piece of text, ask the guide's question — [what is this text?](GUIDE.md#choosing-and-using-type). A 13px paragraph in a table is `body.sm` (14px), not "close to caption". Typical mappings:

   | You find | It is usually | Because |
   |---|---|---|
   | 11–12px grey meta text | `caption.md` | Short supporting detail |
   | 13–14px table text | `body.sm` | Text people read in cells |
   | 13–14px button or field label | `label.md` | Text people act on |
   | 15–16px paragraphs | `body.md` | Reading text |
   | 16–18px bold card titles | `title.md` | Names a component |
   | 20–24px page title | `heading.lg` | Names the page (it grows on wide screens) |
   | Numbers in a mono font | `numeric.*` | Tabular figures align without changing font |

3. **Remove the leftovers.** Once a component uses styles, delete its own `font-size`, `line-height`, `letter-spacing`, `font-family` and any media queries that resized text.
4. **Check the rendered page.** `npm run audit:type -- page.html` measures size, line height and line length at desktop and 320px wide, checks that tabular figures exist in the loaded font, then applies the WCAG text-spacing override and 200% text and reports anything cut off or scrolling sideways. `--shots dir` saves what it saw.
5. **Need a style that doesn't exist?** Don't hand-set one. Check the guide again; if nothing fits, add a style in the engine config ([Readers' settings and brands](GUIDE.md#readers-settings-and-brands)) so it is computed and checked like the rest.

## Checking in CI

The type checker exits with code 1 on any error, so it can gate a pull request. It has no dependencies — copy
`engine/src/lint/type-lint.js` into your repo next to the `typography.contract.json` you ship:

```yaml
# .github/workflows/type.yml
name: Type
on: pull_request
jobs:
  type:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: node tools/type-lint.js src --contract design/typography.contract.json
```

A file can switch off named rules with a comment, for pages like a style specimen: `<!-- ds-lint-ignore: TR-06 -->`.
Use it rarely and say why next to it.

**What the checker can't see:** it reads source, one rule or class list at a time. Text whose size comes from a parent,
a heading that is really just bold text, reading width set somewhere else, and anything that only breaks at 200% or with
the spacing override need the type audit or a review (the [review prompt](../../04-ai-layer/typography/prompts/review-type.md) is written for exactly those).

## Pull-request checklist

- [ ] No `font-size`, `line-height`, `letter-spacing` or `font-family` values — styles only (classes, `text-<style>` utilities, or all five variables of one style).
- [ ] No Tailwind `text-sm`/`text-lg`…, `leading-*`, `tracking-*`, `font-light`.
- [ ] Paragraphs and help text use body, caption or code styles; nothing under 12px.
- [ ] Heading tags follow the outline, no skipped levels; one display style at most.
- [ ] Numbers people compare use tabular numerals; numeric columns right-aligned.
- [ ] Running text within `layout.measure.reading`; not justified.
- [ ] No fixed heights on text; truncated text stays available.
- [ ] Zoom not blocked.
- [ ] `npm run lint:type` and `npm run audit:type` pass.

## Figma

- Open `02-foundations/figma/ds-typography-foundation.fig`: it has the variables and the 21 text styles, each bound to its Responsive variables. (Importing `figma/*.tokens.json` as the engine README describes gives the variables, but text styles can't be imported that way.)
- Set a frame's **Responsive** mode to see a design at another breakpoint; every text style inside follows.
- Once, after opening the file: in the three `type/numeric/*` text styles set **Details → Numbers → Tabular**. The `.fig` format can't carry that setting yet.

## When something's missing

- **A style you need doesn't exist** → add it in the engine config (`typography.styles`): a name by job, a step, a kind and a weight. The build computes the sizes and refuses anything under 12px, a copy of an existing style, or capitals in reading text.
- **A different font** → set `typography.sans` / `typography.mono` and rebuild. Check the font has tabular figures (the type audit tells you) and set `typography.charWidth` to its average character width.
- **Headings feel too big or small** → change `typography.ratio` per breakpoint. The build stops if the largest display no longer fits a phone (L1) or neighbouring styles collide (T7).
