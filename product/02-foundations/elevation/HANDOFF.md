# Elevation · developer handoff

How to take ds elevation from Figma into code and keep it correct. Read the [guide](GUIDE.md) first if you haven't — this
page assumes you know the six levels, why Dark shows height by surface, and why whatever floats keeps an edge. A working
page that uses everything below is in [demo/](demo/index.html): cards with popover menus, a dialog with a menu inside it,
a toast after it and a list you can drag, with switches for Light / Dark and a forced-colours preview, and a readout of
what each level computes to. `demo/shots/` has what the elevation audit saw: the page in Light, the dialog with its menu
open in Dark, and the dialog in Chromium's real forced colours.

---

## What you get

All generated by the engine (`npm run build` → `engine/out/<name>/`). Never edit them by hand.

| File | What it is | Who uses it |
|---|---|---|
| `tokens.css` | Each level's surface, shadow and edge (`--ds-elevation-<job>-surface`, `-shadow`, `-border`), the scrim (`--ds-elevation-modal-scrim`), the layers (`--ds-layer-sticky` … `-dragging`), the classes `.ds-raised`, `.ds-sticky`, `.ds-floating`, `.ds-modal`, `.ds-dragging`, `.ds-scrim` | Every web project |
| `tailwind.theme.css` | `bg-elevation-<job>-surface`, `shadow-raised` … `shadow-dragging`, `border-elevation-<job>-border`, `backdrop:bg-elevation-modal-scrim`; Tailwind's own `shadow-*`, `drop-shadow-*` and `inset-shadow-*` removed | Tailwind projects |
| `tokens.json` | All tokens in the W3C design-token format | Other platforms, Style Dictionary |
| `figma/Elevation.Value.tokens.json` | The Elevation collection for Figma (surfaces scoped to fills, edges to strokes, shadow numbers to effects) | Design |
| `ai/rules/elevation.md`, `ai/elevation.contract.json` | The elevation rulebook and contract for AI tools and the elevation checker | AI tools, the elevation checker |
| `report.html`, `report.json` | Every elevation check (E1–E6) item by item | Reviews, audits |

## Install

The same `tokens.css` as the other foundations — nothing extra to load. Tailwind v4:

```css
@import "tailwindcss";
@import "./tokens.css";
@import "./tailwind.theme.css";
```

## Take the whole level

Use the class. It carries the surface, the shadow, the edge and the place in the stacking order together, so nothing can
be left out:

| Level | Class | Use it for | Tailwind |
|---|---|---|---|
| raised | `.ds-raised` | cards, panels, table frames in the flow | `bg-elevation-raised-surface shadow-raised` |
| sticky | `.ds-sticky` (`data-stick="end"` along the bottom) | the page header, toolbars, sticky table headers | `sticky top-0 z-(--ds-layer-sticky) bg-elevation-sticky-surface shadow-sticky border-b-line border-elevation-sticky-border` |
| floating | `.ds-floating` (`data-layer="toast"` for a toast) | menus, popovers, tooltips, toasts, the nav drawer | `z-(--ds-layer-floating) bg-elevation-floating-surface shadow-floating border-line border-elevation-floating-border` |
| modal | `.ds-modal` on a `<dialog>` | dialogs, sheets, modal drawers | `z-(--ds-layer-modal) bg-elevation-modal-surface shadow-modal border-line border-elevation-modal-border backdrop:bg-elevation-modal-scrim` |
| dragging | `.ds-dragging` while held | an item being dragged (keeps its own surface) | `relative z-(--ds-layer-dragging) shadow-dragging border-line border-elevation-dragging-border` |

The page itself is `elevation.page` (`--ds-elevation-page-surface`, the canvas): no class, no shadow.

```css
/* If a component can't take the class, take all of the level's parts — never the shadow alone. */
.combo-list { background: var(--ds-elevation-floating-surface); box-shadow: var(--ds-elevation-floating-shadow);
  border: var(--ds-border-width-line) solid var(--ds-elevation-floating-border); }
```

No shadow written by hand, no `--ds-color-shadow-*` in a shadow, no Tailwind `shadow-sm` … `shadow-2xl` (they are removed
from the theme): the checker flags all three (ER-01, ER-02).

## Menus, popovers and toasts: the top layer

Open anything that floats with the `popover` attribute. The browser puts it in the top layer — above every z-index, never
clipped by a parent with `overflow: hidden` or `auto` — and gives you light dismiss and Escape:

```html
<button class="btn" popovertarget="row-menu" aria-label="More actions for INV-1042">⋯</button>
<div class="ds-floating menu" id="row-menu" popover aria-label="INV-1042">…</div>
```

```css
.menu { margin: 0; }
.menu:popover-open { position: fixed; inset: auto; }   /* place it next to its button (JS below, or CSS anchor positioning) */
```

```js
menu.addEventListener('toggle', (e) => {
  if (e.newState !== 'open') return;
  const r = button.getBoundingClientRect();
  menu.style.left = `${Math.max(8, Math.min(r.right - menu.offsetWidth, innerWidth - menu.offsetWidth - 8))}px`;
  menu.style.top = `${r.bottom + 4}px`;
});
```

A toast is `popover="manual"` (it doesn't close on a click elsewhere), `role="status"`, `data-layer="toast"`, and is
shown **after** any open dialog — the most recently opened thing in the top layer is on top. It must need no action:
while a dialog is open, everything outside it is inert.

## Dialogs

```html
<dialog class="ds-modal" id="void-dialog" aria-labelledby="void-title">
  <form method="dialog">
    <h2 id="void-title">Void INV-1042?</h2>
    <button value="keep">Keep it</button> <button value="void">Void invoice</button>
  </form>
</dialog>
```

```js
openButton.addEventListener('click', () => dialog.showModal());
dialog.addEventListener('close', () => { openButton.focus(); if (dialog.returnValue === 'void') showToast(); });
```

`showModal()` gives you the top layer, the `::backdrop` (tokens.css paints it with the scrim), an inert page, focus moved
in and Escape. You add the label and focus back to the opener. Never `dialog.show()` or the `open` attribute for anything
that must be answered (ER-06). If a modal can't be a `<dialog>`: `role="dialog" aria-modal="true"`, a `.ds-scrim` just
before it, focus moved in and held, the rest of the page `inert`, Escape, and focus returned.

A menu inside a dialog is a popover too: opened after the dialog, it goes above it.

## Layers, for everything else

| Layer | z-index | For |
|---|---|---|
| `--ds-layer-sticky` | 100 | sticky bars and the page header |
| `--ds-layer-floating` | 200 | floating things that can't be popovers (a drawer pane) |
| `--ds-layer-modal` | 300 | a modal that isn't a `<dialog>`, and its `.ds-scrim` |
| `--ds-layer-toast` | 400 | a toast that isn't a popover |
| `--ds-layer-dragging` | 500 | an item while it is dragged |

`z-index` is always a layer (Tailwind `z-(--ds-layer-floating)`), or −1, 0, 1, 2 for order inside one component (a
table's own sticky header row, the lifted part of a `.ds-join` group). Never 999 or 9999 (ER-05). Sticky bars cover what
scrolls under them, so tokens.css adds the header and the focus ring's reach to the scroll padding; if your header grows
(two rows, bigger text), measure it — `new ResizeObserver(pad).observe(header)` — or focused items land under it
(WCAG 2.4.11).

## Dark mode

Nothing to do. Every level's surface, edge and shadow colour switches with the theme, and in Dark the surfaces get
lighter as they rise (each at least 1.1:1 over the level below). Don't write `[data-theme="dark"]` or
`prefers-color-scheme` rules for shadows or level surfaces (ER-07): a darker shadow measures almost nothing on the Dark
page.

## Hover, press, focus and drag

- Hover on something clickable changes its fill (`--ds-color-bg-surface-hover`) or a border colour; the shadow may grow
  one level with it, never alone (ER-08):
  `.card:has(a:hover) { background: var(--ds-color-bg-surface-hover); box-shadow: var(--ds-elevation-sticky-shadow); }`
- Press goes back to the resting shadow, never higher.
- Focus is the ring tokens.css draws — never a shadow.
- Dragging: add `.ds-dragging` while held and remove it on drop; give a second way to move the item (buttons or arrow
  keys — WCAG 2.5.7) and say where it went in a live region.

## Forced colours

Windows contrast themes remove every `box-shadow` and replace surfaces with the system page colour: every level looks
flat. Borders stay. `tokens.css` already draws the edge of `.ds-floating`, `.ds-modal` and `.ds-dragging` on every side,
`.ds-sticky`'s line toward the content, and the `.ds-shell` drawer's edge. You: never remove those borders (ER-04), never
show hover, selection or focus by shadow alone, and keep floating surfaces opaque — no `backdrop-filter`, no translucent
backgrounds (ER-09).

## Adding a layer

```json
{ "elevation": { "layers": [
  { "name": "layer.banner", "above": "sticky", "description": "A site-wide banner that stays above sticky bars" } ] } }
```

The build computes its number (here 150, between sticky and floating), keeps the order, and refuses numbers, names by
position (`top`, `high`, `z-50`), two layers claiming the same spot and anything else in `elevation` — levels, surfaces
and shadows are computed. Most things fit an existing level as a popover; see the [Add a layer prompt](../../04-ai-layer/elevation/prompts/add-a-layer.md).

## Moving an existing product to ds elevation

1. **Find what's there.** `npm run lint:elevation -- path/to/src` lists hand-made shadows, shadows built from the shadow
   colours, a level's shadow on another level's surface, floating things with no edge, stray z-indexes, dialogs opened
   without `showModal()` or without a label, dark-mode overrides, hover by shadow alone, glass and redefined variables.
2. **Map every lifted thing to a level.** Cards and panels → raised; headers and toolbars → sticky; menus, popovers,
   tooltips, toasts → floating as popovers; dialogs → modal on `<dialog>`; drag → dragging. Delete shadows that space,
   a surface change or a line already do.
3. **Untangle the stacking.** Move what opens over content into the top layer, give the rest layer tokens, delete the
   numbers ([Fix the stacking prompt](../../04-ai-layer/elevation/prompts/fix-the-stacking.md)).
4. **Check the rendered page.** `npm run audit:elevation -- page.html --open "#menu-button" --open "#delete then #confirm"`
   renders it in Light, Dark and forced colours at 1280 and 320px; measures every shadow, surface step and edge against
   what is really behind it; opens every popover and each `--open` (a `then` chain clicks one thing after another, from
   a fresh page each time); checks that open things are on top and not clipped, that dialogs are modal, labelled, hold
   focus, close on Escape and give focus back; and tabs both ways to check nothing focused hides under a sticky bar.
   `--shots dir` saves what it saw.

## Checking in CI

The elevation checker exits with code 1 on any error and has no dependencies — copy `engine/src/lint/elevation-lint.js`
next to the `elevation.contract.json` you ship:

```yaml
      - run: node tools/elevation-lint.js src --contract design/elevation.contract.json
```

`ds-lint-ignore: ER-xx` anywhere in a file switches one rule off for that file — leave a comment saying why. The audit
needs Playwright (`npm i -D playwright`) and a built page; run it on pages with menus, dialogs and sticky bars before
release.
