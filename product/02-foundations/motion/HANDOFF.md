# Motion · developer handoff

How to take ds motion from Figma into code and keep it correct. Read the [guide](GUIDE.md) first if you haven't — this
page assumes you know the six jobs, why a duration follows the distance, and what reduced motion does (fade only). A
working page that uses everything below is in [demo/](demo/index.html): buttons and rows that answer a hover, an
accordion, tabs and a task list that change in place, a menu, a toast and a dialog with a menu inside it that open and
close through tokens.css, a count that highlights when it changes and an export with a loading indicator — with switches
for the motion setting (your device / reduced / full) and for watching at a fifth of the speed, and a readout of what
each job resolves to now and which job the last animation used. `demo/shots/` has what the motion audit saw.

---

## What you get

All generated by the engine (`npm run build` → `engine/out/<name>/`). Never edit them by hand.

| File | What it is | Who uses it |
|---|---|---|
| `tokens.css` | Each job's duration, curve and distance (`--ds-motion-<job>-duration`, `-easing`, `-distance`, and `-exit-duration`, `-exit-easing` for floating and modal) with full and reduced values; the ready transitions for `.ds-floating` popovers, toasts, `dialog.ds-modal` and its scrim, and the `.ds-shell` drawer; `.ds-loading` and `.ds-highlight` | Every web project |
| `tailwind.theme.css` | `ease-<job>` and `ease-<job>-exit`; plain `transition` utilities default to the feedback job; Tailwind's own `ease-in`, `ease-out`, `ease-in-out` and `animate-*` removed | Tailwind projects |
| `tokens.json` | All tokens in the W3C design-token format (durations, cubic-bezier curves, dimensions) | Other platforms, Style Dictionary |
| `figma/Motion.full.tokens.json`, `figma/Motion.reduced.tokens.json` | The Motion collection's two modes for Figma | Design |
| `ai/rules/motion.md`, `ai/motion.contract.json` | The motion rulebook and contract for AI tools and the motion checker | AI tools, the motion checker |
| `report.html`, `report.json` | Every motion check (M1–M6) item by item | Reviews, audits |

## Install

The same `tokens.css` as the other foundations — nothing extra to load. Tailwind v4:

```css
@import "tailwindcss";
@import "./tokens.css";
@import "./tailwind.theme.css";
```

## Take the job

Pick by what is changing; the job carries its duration, curve and distance together. Never a number of your own.

| Job | Use it for | CSS | Tailwind |
|---|---|---|---|
| feedback | hover, press, toggles, a selected row — colour, fill, border | `var(--ds-motion-feedback-duration)` `var(--ds-motion-feedback-easing)` | `transition-colors` (its default is this job) |
| change | a panel opening, a tab panel, an item added or removed | `…-change-duration`, `-easing`, `-distance` | `duration-(--ds-motion-change-duration) ease-change` |
| floating | menus, popovers, tooltips, toasts, the nav drawer | ready in tokens.css | — |
| modal | dialogs and sheets | ready in tokens.css | — |
| highlight | a value or row that changed on its own | `.ds-highlight` | `ds-highlight` |
| loading | work in progress | `.ds-loading` | `ds-loading` |

**Feedback** — name the properties; never `transition: all` (MR-02):

```css
.btn { transition: background-color var(--ds-motion-feedback-duration) var(--ds-motion-feedback-easing),
                   border-color var(--ds-motion-feedback-duration) var(--ds-motion-feedback-easing),
                   color var(--ds-motion-feedback-duration) var(--ds-motion-feedback-easing); }
```

A switch's knob jumps to its new side; only its colours transition. Movement is not feedback.

**Change** — the size changes at once, the content arrives by the job's distance (reduced motion sets it to 0, so it
only fades). Never animate `height`, `width`, `margin` or `grid-template-rows` (MR-03):

```css
@keyframes arrive { from { opacity: 0; translate: 0 calc(-1 * var(--ds-motion-change-distance)); } }
.panel:not([hidden]) { animation: arrive var(--ds-motion-change-duration) var(--ds-motion-change-easing); }
```

Removing an item: let it leave the same way (`to { opacity: 0; translate: … }` with `forwards`), then remove it on
`animationend` and move focus to the next item; the list closes the gap at once.

## Opening and closing: nothing to add

Open things the way the Elevation foundation says, and tokens.css animates them both ways:

| What | Markup | What it does |
|---|---|---|
| Menus, popovers, tooltips | `<div class="ds-floating" popover>` + `popovertarget` | drops in from above (`motion.floating`: 4px, 150ms; leaves in 100ms) |
| Toasts | `class="ds-floating" data-layer="toast" popover="manual" role="status"` | comes up from the bottom |
| Dialogs | `<dialog class="ds-modal">` + `showModal()` | rises 16px in 250ms while the scrim fades in; leaves in 150ms |
| The navigation drawer | `[data-shell="nav"]` in `.ds-shell`, opened with `data-open` | in from its own side (flipped right to left) |

Closing keeps the element shown and in the top layer until it has faded (`display` and `overlay` transition with
`allow-discrete`). Browsers that can't do that open and close at once — nothing breaks.

Don't add `transition` or `animation` to these, don't animate them with `element.animate()` or class toggles, and don't
delay moving focus until an animation ends (MR-05). Position menus as before (`.menu:popover-open { position: fixed;
inset: auto; }` plus a few lines of script, or CSS anchor positioning): the movement is a `translate`, so it never fights
your placement.

## Reduced motion

Nothing to do for anything that uses the tokens: the reduced values take over when the reader's system asks for less
motion (`prefers-reduced-motion: reduce`). Every distance becomes 0, transitions fade in 100ms, the loading indicator
pulses instead of turning, highlights fade as before.

**A setting of your own.** Offer "Same as my device / Reduced / Full", write it to `<html data-motion="…">` and remember
it; with nothing set, the device decides (the guide has the snippet). `data-motion="reduced"` on any container previews
the reduced mode inside a page. Never put `data-motion="full"` in your markup by default (MR-10).

**Your own animations.** Anything you animate outside the tokens needs a reduced path, or it keeps moving for people who
asked it to stop (MR-03, MR-04):

```css
@media (prefers-reduced-motion: no-preference) {
  html { scroll-behavior: smooth; }   /* smooth scrolling only for people who haven't asked for less motion */
}
```

Tailwind: put `motion-safe:` in front of anything that moves (`motion-safe:scroll-smooth`). Tailwind's `motion-safe:`
follows the device setting only; prefer the tokens, which also follow `data-motion`.

## Loading and highlights

```html
<p role="status"><svg class="ds-loading" aria-hidden="true" …></svg> Exporting…</p>
```

- Show the indicator only while the work runs, and stop it when the work ends.
- Work that can take longer than five seconds says how far it got — in words or a bar (WCAG 2.2.2).
- `.ds-loading` is the only loop. Anything else that runs on (`animation-iteration-count: infinite`, Tailwind
  `animate-*`) needs a pause or stop control, or must end within five seconds (MR-06). Tailwind's `animate-spin`,
  `animate-ping`, `animate-pulse` and `animate-bounce` are removed from the theme.

```js
// A value that changed on its own: one highlight per change, at most once per motion.highlight.
el.classList.remove('ds-highlight');
requestAnimationFrame(() => el.classList.add('ds-highlight'));
```

Never blink, shake, bounce or pulse something to get attention, and never roll digits (MR-07, MR-08). An error is a
message and the state border (Border foundation), not a shake.

## What never moves

- Focus rings: they appear at once — never in a transition list (MR-02).
- The page while it scrolls: no parallax, no scroll-linked movement, no scroll handlers that `translate` (MR-09).
- Text being read: no auto-advancing carousels, no marquees, no video that plays by itself without controls.
- Size: nothing grows, shrinks, rotates or skews to make a point; only the loading indicator turns.

## Adding a job

```json
{ "motion": { "jobs": [
  { "name": "motion.carousel", "kind": "in-place", "distance": "space.6", "description": "Slides of a carousel the reader steps through" } ] } }
```

`kind` is `in-place` (it changes where it is: one duration, the standard curve) or `in-out` (it arrives and leaves: enter
and exit durations and curves). The build computes the duration from the distance (here 250ms for 24px), the reduced
values (0px, 100ms), and refuses durations, curves, names by look or speed (`fast`, `bounce`, `200ms`), loops, distances
off the spacing scale and anything further than 32px. See the [Add a job prompt](../../04-ai-layer/motion/prompts/add-a-job.md).

## Moving an existing product to ds motion

1. **Find what's there.** `npm run lint:motion -- path/to/src` lists durations and curves written by hand, primitives,
   `transition: all`, focus rings that transition, movement that isn't a job's distance (scale, rotate, `vh` slides,
   animated layout), animations with no reduced path or a reduced path that still moves, motion of its own on popovers and
   dialogs, loops, flashes, shakes and repeated highlights, smooth scrolling for everyone, parallax, autoplay, redefined
   variables and a forced `data-motion="full"`.
2. **Map every motion to a job.** Hover and press → feedback; panels, tabs and lists → change; menus, popovers, toasts
   → floating (delete their own transitions: tokens.css has them); dialogs → modal; a changed value → highlight; spinners
   → `.ds-loading`. Delete motion nobody would miss.
3. **Fix what moves** ([Fix the motion prompt](../../04-ai-layer/motion/prompts/fix-the-motion.md)): replace numbers with
   jobs, translate by the job's distance, put your own movement behind `prefers-reduced-motion: no-preference`, stop loops.
4. **Check the rendered page.** `npm run audit:motion -- page.html --open "#menu-button" --open "#delete then #confirm"`
   renders it with full and reduced motion at 1280 and 320px; hovers every control, tabs through the page, opens every
   popover and each `--open` (a `then` chain, from a fresh page each time) and closes them; pauses every animation and
   steps it frame by frame to measure how far it really moves, whether it turns, which job its duration and curve belong
   to, and — from screenshots — how often it flashes; checks that nothing moves with the scroll, that smooth scrolling is
   off with reduced motion and that no video plays by itself. `--shots dir` saves what it saw.

## Checking in CI

The motion checker exits with code 1 on any error and has no dependencies — copy `engine/src/lint/motion-lint.js` next to
the `motion.contract.json` you ship:

```yaml
      - run: node tools/motion-lint.js src --contract design/motion.contract.json
```

`ds-lint-ignore: MR-xx` anywhere in a file switches one rule off for that file — leave a comment saying why (a carousel
with its own pause button, say, for MR-06). The audit needs Playwright (`npm i -D playwright`) and a built page; run it on
pages with menus, dialogs and anything that animates before release.
