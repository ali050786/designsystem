# Spacing · developer handoff

How to take ds spacing from Figma into code and keep it correct. Read the [guide](GUIDE.md) first if you haven't — this page
assumes you know what the families, the ladder and density are. A working page that uses everything below is in
[demo/](demo/index.html); it has a density switch (comfortable / default / compact), a 200% text switch and a "show targets"
switch, and every value on it is read live from the page.

---

## What you get

All generated by the engine (`npm run build` → `engine/out/<name>/`). Never edit them by hand.

| File | What it is | Who uses it |
|---|---|---|
| `tokens.css` | Every spacing token as a CSS variable, in px; the default density on `:root` and one block per density, `[data-density="…"]`, that works on any element | Every web project |
| `tailwind.theme.css` | Spacing utilities named by job: `p-inset-*`, `gap-y-stack-*`, `gap-x-inline-*`, and `min-h-control`, `min-w-control`, `gap-icon`, `min-w-target`, `min-h-target` | Tailwind projects |
| `tokens.json` | All tokens in the W3C design-token format; the other densities in `$extensions` | Other platforms, Style Dictionary |
| `figma/Density.<mode>.tokens.json` | The Density variables per mode, for Figma | Design |
| `ai/rules/spacing.md`, `ai/spacing.contract.json` | The spacing rulebook and contract for AI tools and the spacing checker | AI tools, the spacing checker |
| `report.html`, `report.json` | Every spacing check, per token and density | Reviews, audits |

## Install

The same `tokens.css` as colour and type — nothing extra to load.

```html
<link rel="stylesheet" href="/css/tokens.css">
```

Tailwind v4, in your main CSS file:

```css
@import "tailwindcss";
@import "./tokens.css";
@import "./tailwind.theme.css";
```

## Density

Density is a mode, like the colour theme. Without an attribute, the page uses the default density from the engine config.

```html
<html data-density="compact">                      <!-- the whole product -->
<div class="table-wrap" data-density="compact">     <!-- one region: everything inside follows, nothing outside changes -->
```

Valid values: `comfortable`, `default`, `compact`. The spacing checker flags anything else.

**Offering density as a setting.** If people can choose it, store their choice and set the attribute on `<html>` before
the first paint, so the page doesn't jump:

```html
<script>try { const d = localStorage.getItem('density'); if (d) document.documentElement.dataset.density = d; } catch {}</script>
```

**In Figma**, select a frame and set its **Density** mode in the Variables section of the right panel. Every padding, gap and
size bound to a Density variable inside it changes; frames left on Auto use the default density.

## Names: Figma → CSS → Tailwind

Take the Figma variable name, replace `/` with `-`, and prefix it.

| Figma variable | CSS variable | Tailwind |
|---|---|---|
| `space/inset/md` | `--ds-space-inset-md` | `p-inset-md`, `px-inset-md`, `py-inset-md` … |
| `space/stack/lg` | `--ds-space-stack-lg` | `gap-y-stack-lg`, `space-y-stack-lg`, `mt-stack-lg`, `mb-stack-lg` |
| `space/inline/sm` | `--ds-space-inline-sm` | `gap-x-inline-sm`, `space-x-inline-sm`, `ml-inline-sm`, `mr-inline-sm` |
| `size/control/height` | `--ds-size-control-height` | `min-h-control`, `min-w-control` |
| `size/control/icon-gap` | `--ds-size-control-icon-gap` | `gap-icon` |
| `size/target/min` | `--ds-size-target-min` | `min-w-target`, `min-h-target` |

Tailwind lets any spacing utility take any spacing value, so `p-stack-md` would compile. The spacing checker holds code to the
family: padding utilities take inset, vertical ones stack, horizontal ones inline. `gap-*` with one value may take stack or
inline. Never use Tailwind's own numeric scale (`p-4`, `gap-2`, `mt-[13px]`): it is in rem and ignores density.

## Patterns

Each pattern is in the [demo](demo/index.html), working in every density, at 320px and at 200% text.

### Pad the container

```css
.card  { padding: var(--ds-space-inset-lg); }
.badge { padding: var(--ds-space-inset-xs) var(--ds-space-inset-sm); }   /* short labels: tighter above and below */
```

The space between a container's edge and its content is the container's padding, never a margin on its first child.

### Gaps on the parent

```css
.form  { display: grid; gap: var(--ds-space-stack-xl); }   /* between groups */
.group { display: grid; gap: var(--ds-space-stack-lg); }   /* between fields */
.field { display: grid; gap: var(--ds-space-stack-xs); }   /* label, input, help: parts of one field */
```

```html
<form class="form">
  <fieldset class="group">
    <legend>Profile</legend>                          <!-- the markup groups what the spacing groups -->
    <div class="field">
      <label for="email">Email</label>
      <input id="email" aria-describedby="email-help">
      <span id="email-help">We only use it to send what you choose below.</span>
    </div>
  </fieldset>
</form>
```

A legend sits outside its fieldset's gap; give it `margin-bottom: var(--ds-space-stack-md)`.

### Rows that wrap

```css
.toolbar { display: flex; flex-wrap: wrap; gap: var(--ds-space-stack-sm) var(--ds-space-inline-xl); }  /* row gap, column gap */
.toolbar .group { display: flex; flex-wrap: wrap; gap: var(--ds-space-stack-sm) var(--ds-space-inline-sm); }
```

Never shrink a gap to make a row fit — let it wrap. For right-to-left languages use `column-gap` and the logical margins
(`margin-inline-start`, `margin-inline-end`) so the space flips with the text.

### Controls

```css
.btn {
  display: inline-flex; align-items: center; justify-content: center;
  min-height: var(--ds-size-control-height);                              /* a minimum: grows with its label */
  padding: var(--ds-space-inset-xs) var(--ds-space-inset-md);             /* the sides; a little above and below for wrapped labels */
  gap: var(--ds-size-control-icon-gap);
}
.icon-btn { min-width: var(--ds-size-control-height); padding: 0; }       /* square, still a minimum */
input, select { min-height: var(--ds-size-control-height); padding: var(--ds-space-inset-xs) var(--ds-space-inset-md); }
```

Never `height: 40px` or `height: var(--ds-size-control-height)`: at 200% text a label line is twice as tall and a fixed box
cuts it off. Match the label to the density: `label.lg` in comfortable, `label.md` in default and compact (Typography).

### Small marks get a hit area

```css
.check { display: inline-flex; align-items: center; gap: var(--ds-space-inline-sm);
  min-width: var(--ds-size-target-min); min-height: var(--ds-size-target-min); }      /* the label is the target */
.check input { inline-size: 1.125em; block-size: 1.125em; margin: 0; }
.close { min-width: var(--ds-size-target-min); min-height: var(--ds-size-target-min); }
```

A checkbox can be drawn small as long as the area that reacts to a click is at least 24 × 24px — wrap it in its label. Links
inside a sentence are the one exception WCAG allows.

### Page edges and sections

Horizontal page margins come from `--ds-layout-margin` (per breakpoint, linked to the same scale). Vertical rhythm between
sections is `space.stack.2xl`; the space above and below a page's content is `space.inset.2xl`. Paragraphs are
`space.stack.lg` apart (one line of `body.md`), never separated by empty lines.

```css
main { padding: var(--ds-space-inset-2xl) var(--ds-layout-margin); display: grid; gap: var(--ds-space-stack-2xl); }
main > * { min-width: 0; }   /* wide content scrolls inside its card instead of widening the page */
```

The last line matters more with density: comfortable makes everything wider, and a grid item that can't shrink pushes the
page sideways at 320px. The spacing audit checks reflow in every density.

## Moving an existing product to ds spacing

Work screen by screen — a token is chosen by the relationship between two things, which you can only see on the screen.

1. **Find what's there.** `npm run lint:space -- path/to/your-app/src` lists every hand-set padding, margin and gap,
   Tailwind numeric utility, fixed control height and spacer element, with line numbers.
2. **Pick by job, not by nearest value.** Ask the guide's two questions: [which way does the space run, and how closely do
   the two things belong together?](GUIDE.md#choosing-and-using-space) Typical mappings:

   | You find | It is usually | Because |
   |---|---|---|
   | 2–6px between a label and its input | `stack.xs` | Parts of one field |
   | 8–12px between list rows or menu items | `stack.sm` | Items of one group |
   | 12–20px between form fields | `stack.lg` | Fields in a form |
   | 24px+ between groups or sections | `stack.xl` / `stack.2xl` | A new group or section |
   | 16px or 24px card padding | `inset.lg` | A card |
   | 8px horizontal padding on a menu item | `inset.sm` | A menu item |
   | 36–44px button height | `size.control.height` as min-height | A control |
   | 6–8px between buttons | `inline.sm` | Items of one group |

3. **Remove the leftovers.** Once a component uses tokens, delete its own px values, its `.compact` variants and any
   media queries that only changed spacing.
4. **Check the rendered page.** `npm run audit:space -- page.html` renders it in all three densities at 1280 and 320px, measures
   every target against WCAG 2.5.8, flags controls shorter than the density's control height, lists spacing that stays the
   same in every density (hand-set or a primitive), and checks labels still fit at 200% text in compact. `--shots dir` saves
   what it saw.
5. **Need a size that doesn't exist?** Don't hand-set one. If nothing in the guide fits, add a token in the engine config
   ([Readers' settings and products](GUIDE.md#readers-settings-and-products)) so it is computed and checked like the rest.

## Checking in CI

The spacing checker exits with code 1 on any error. It has no dependencies — copy `engine/src/lint/space-lint.js` into your
repo next to the `spacing.contract.json` you ship:

```yaml
# .github/workflows/spacing.yml
name: Spacing
on: pull_request
jobs:
  spacing:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: node tools/space-lint.js src --contract design/spacing.contract.json
```

A file can switch off named rules with a comment, for pages like a specimen: `<!-- ds-lint-ignore: SR-07 -->`. Use it
rarely and say why next to it.

**What the checker can't see:** it reads source, one rule or class list at a time. Whether a size fits the relationship
(stack.lg between a label and its own field), whether markup groups what spacing groups, targets that are small because of
their content, and layouts that only break in one density need the spacing audit or a review (the
[review prompt](../../04-ai-layer/spacing/prompts/review-space.md) is written for exactly those).

## Pull-request checklist

- [ ] No px, rem or em in padding, margin or gap — tokens only (CSS variables or `p-inset-*` / `gap-y-stack-*` / `gap-x-inline-*`).
- [ ] No Tailwind numeric spacing (`p-4`, `gap-2`, `mt-[13px]`), no primitives (`--ds-space-4`) in components.
- [ ] Padding uses inset, vertical gaps stack, horizontal gaps inline.
- [ ] Inside a group is smaller than between groups; the markup groups what the spacing groups.
- [ ] Density comes from `data-density`, never from a `.compact` class or swapped token names.
- [ ] Every target is at least 24 × 24px; controls use `min-height`, never `height`.
- [ ] No spacer elements, `<br>` runs or `&nbsp;` for space; no spacing variables redefined.
- [ ] `npm run lint:space` and `npm run audit:space` pass.

## Figma

- Open `02-foundations/figma/ds-spacing-foundation.fig`. It has the Primitives (the scale, hidden from publishing) and Density
  (default, comfortable, compact) collections, plus Color, Responsive and the type styles its own text uses.
- Bind padding and gaps to `space/*` variables and control sizes to `size/*`: spacing variables are scoped to Gap (padding and
  auto-layout gaps), size variables to width and height, so pickers only offer the right ones.
- Set a frame's **Density** mode to see a design in another density. The cover and the Density chapter show one card in all
  three modes — nothing was redrawn.

## When something's missing

- **A size you need doesn't exist** → add it in the engine config (`spacing.tokens`): a family (inset, stack, inline), a size
  from 2xs to 4xl and a `base` on the scale. The build computes compact and comfortable, refuses px, other families and
  existing names, and fails if the token breaks the ladder.
- **The product should start compact (or comfortable)** → set `density.default` and rebuild; `:root` and Figma's default
  mode follow.
- **Compact should be tighter** → `spacing.densityStep: 2` is allowed, but with the default ladder the build stops: compact
  `inset.xs` would reach 0px and compact controls would leave 2px around their label. Tighten single components in the
  component layer instead.
