# Radius · developer handoff

How to take ds radius from Figma into code and keep it correct. Read the [guide](GUIDE.md) first if you haven't — this page
assumes you know the six roles, the three styles and the nested rule. A working page that uses everything below is in
[demo/](demo/index.html): it has switches for the radius style, the density and the text direction, and reads back the
radii the page is using.

---

## What you get

All generated by the engine (`npm run build` → `engine/out/<name>/`). Never edit them by hand.

| File | What it is | Who uses it |
|---|---|---|
| `tokens.css` | The radius scale (`--ds-radius-*`), the roles (`--ds-shape-*`) in the product's style on `:root`, a `[data-radius="sharp\|default\|round"]` block for each style, the focus-ring radii (`--ds-shape-*-focus`) and the `.ds-join` class | Every web project |
| `tailwind.theme.css` | `rounded-none`, `-mark`, `-control`, `-container`, `-surface`, `-pill` (and their side and corner forms). Tailwind's own radius scale is removed (`--radius-*: initial`) | Tailwind projects |
| `tokens.json` | All tokens in the W3C design-token format, other styles in `$extensions.org.ds.modes` | Other platforms, Style Dictionary |
| `figma/Shape.<style>.tokens.json` | The Shape collection per style, for Figma | Design |
| `ai/rules/radius.md`, `ai/radius.contract.json` | The radius rulebook and contract for AI tools and the radius checker | AI tools, the radius checker |
| `report.html`, `report.json` | Every radius check (R1–R4), item by item | Reviews, audits |

## Install

The same `tokens.css` as colour, type, spacing and layout — nothing extra to load. Tailwind v4:

```css
@import "tailwindcss";
@import "./tokens.css";
@import "./tailwind.theme.css";
```

## Roles

Pick by what the thing is, never by size. Values in px for this build's styles:

| Role | CSS | Tailwind | Use it for |
|---|---|---|---|
| `shape.none` | `var(--ds-shape-none)` | `rounded-none` | Tables and cells, full-bleed media, dividers, the edges where joined parts meet |
| `shape.mark` | `var(--ds-shape-mark)` | `rounded-mark` | Checkboxes, colour swatches, `<kbd>`, inline code |
| `shape.control` | `var(--ds-shape-control)` | `rounded-control` | Buttons, inputs, selects, tabs, menu items, chips |
| `shape.container` | `var(--ds-shape-container)` | `rounded-container` | Cards, panels, table frames, menus, popovers, tooltips, toasts |
| `shape.surface` | `var(--ds-shape-surface)` | `rounded-surface` | Dialogs, sheets, drawers |
| `shape.pill` | `var(--ds-shape-pill)` | `rounded-pill` | Badges, counters, toggle tracks, avatars — labels that never wrap |

```css
.btn  { border-radius: var(--ds-shape-control); }
.card { border-radius: var(--ds-shape-container); }
input[type="checkbox"] { border-radius: var(--ds-shape-mark); }   /* never the control radius: in round it is a circle */
```

**Buttons are never pills.** A button can wrap (a long translation, 200% text on a phone); round ends then cut its first and
last letters off the fill. Keep the pill for badges, counters and avatars — and let an avatar grow with its text
(`min-inline-size`, `min-block-size`, `aspect-ratio: 1`, never a fixed width and height).

## Switching style

The product's style is set once in the engine config (`"radius": { "style": "round" }`) and lands on `:root`. To preview
another style on one region — a theme picker, a marketing page — put `data-radius` on it:

```html
<article class="card" data-radius="round">…</article>
```

Everything inside switches together. Don't use it to make one component rounder than the rest.

## Nested corners

A shape that **fills** a rounded parent — a panel in a card, an item in a menu, a segment in a segmented control — with
padding smaller than the parent's radius takes the parent's radius minus the padding. Write it on the tokens, so it follows
density and style:

```css
.menu      { border-radius: var(--ds-shape-container); padding: var(--ds-space-inset-xs); }
.menu a    { border-radius: max(0px, var(--ds-shape-container) - var(--ds-space-inset-xs)); }
```

Tailwind: `rounded-[max(0px,var(--radius-container)-var(--spacing-inset-xs))]`.

With the default ladder, a control inside a container padded with `inset.xs` comes out at the control radius in default and
round (8 − 4 = 4, 12 − 4 = 8) — the segmented controls in the demos use that.

**Flush children** take the parent's radius on the corners they share, and nothing clips:

```css
.card-head { border-start-start-radius: var(--ds-shape-container); border-start-end-radius: var(--ds-shape-container); }
thead th:first-child { border-start-start-radius: var(--ds-shape-container); }
thead th:last-child  { border-start-end-radius: var(--ds-shape-container); }
```

**Don't round a card by clipping it.** `overflow: hidden` on a rounded container cuts the focus ring of anything within 4px
of its edge (the ring sits 2–4px outside the element). Clip an image itself if you must (`border-radius` on the `<img>`).

## Joined parts

```html
<div class="ds-join" role="group" aria-label="View">
  <button class="btn" aria-pressed="true">List</button>
  <button class="btn" aria-pressed="false">Board</button>
</div>
<div class="ds-join" data-join="block">…stacked items…</div>
```

`.ds-join` squares the edges where parts meet with logical corners (so it flips in right-to-left), and lifts the focused part
above its neighbours — without that, the next button is painted over the focused one's ring (the radius audit found it).
Writing your own? Use `border-start-start-radius` and friends (Tailwind `rounded-s-`, `-e-`, `-ss-`, `-se-`, `-es-`, `-ee-`),
never `border-top-left-radius` or `rounded-l-`. A drawer or sheet attached to the start edge rounds only
`border-start-end-radius` and `border-end-end-radius`.

## Focus rings

`tokens.css` draws the ring as an outline on `:focus-visible`; outlines follow `border-radius`, so there's nothing to set.
If a design draws the ring on its own layer, place that layer at the ring's inner edge and draw outwards; its radius is the
role's `-focus` token (the shape plus the ring offset):

```css
.chip { position: relative; border-radius: var(--ds-shape-control); }
.chip:focus-visible { outline: none; }
.chip:focus-visible::after { content: ""; position: absolute; inset: calc(-1 * var(--ds-focus-ring-offset));
  box-shadow: 0 0 0 var(--ds-focus-ring-width) var(--ds-focus-ring-color); border-radius: var(--ds-shape-control-focus); }
```

Prefer the outline: box-shadow rings disappear in forced-colours mode (Border foundation).

**Sticky bars.** `tokens.css` now sets `scroll-padding-top` to the header height **plus** the ring's reach
(offset + width), so a focused item scrolled under the header shows its whole ring. A page with its own sticky bar adds its
height the same way (the demos measure the bar and add the reach).

## Moving an existing product to ds radius

1. **Find what's there.** `npm run lint:radius -- path/to/src` lists hard-coded radii, primitives, Tailwind's own `rounded-*`,
   unknown roles, physical corners, rings on their own layer with the wrong radius, rounded containers that clip, radius
   changes on hover or focus, copied radii inside padded parents and redefined variables.
2. **Map every radius to a role by job.** 2–4px on inputs and buttons → control; 6–12px on cards and menus → container;
   anything on a dialog → surface; `9999px`, `50%`, `rounded-full` → pill (or control, if it is a button).
3. **Fix the nesting.** Children that fill a padded rounded parent get `max(0px, parent − padding)`; flush headers get the
   parent's radius on their shared corners; remove `overflow: hidden` used for rounding.
4. **Check the rendered page.** `npm run audit:radius -- page.html` renders it in all three styles at 1280 and 320px and at
   200% text, and reports radii that don't follow the style, corners that poke out of their parent, nested radii that don't
   follow the rule, text outside its rounded shape, rounded seams in joined groups (in both text directions) and focus
   rings missing on any side — clipped by a container or covered by a neighbour. `--shots dir` saves what it saw.

## Checking in CI

The radius checker exits with code 1 on any error and has no dependencies — copy `engine/src/lint/radius-lint.js` next to
the `radius.contract.json` you ship:

```yaml
      - run: node tools/radius-lint.js src --contract design/radius.contract.json
```

`<!-- ds-lint-ignore: RR-01 -->` switches a rule off for one file (a specimen page). Use it rarely and say why.

**What the checker can't see:** which element fills its parent (it only compares direct parent and child in markup), whether
a clipped container holds focusable content when the content is rendered by script, and anything that depends on the
rendered size (a pill that wraps at 200% text). The audit and the [review prompt](../../04-ai-layer/radius/prompts/review-radius.md)
cover those.

## Pull-request checklist

- [ ] Every `border-radius` is a `--ds-shape-*` role or a nested expression on one (Tailwind `rounded-<role>`).
- [ ] Checkboxes use `shape.mark`; buttons never use `shape.pill`.
- [ ] Children that fill a rounded parent use `max(0px, parent − padding)`; flush children share the parent's corners.
- [ ] No `overflow: hidden` on a rounded container that holds focusable content.
- [ ] Joined parts use `.ds-join` or logical corners.
- [ ] No radius change on hover, focus, active or selected.
- [ ] `npm run lint:radius` and `npm run audit:radius` pass.

## Figma

- Open `02-foundations/figma/ds-radius-foundation.fig`. It has the Primitives (the radius scale, hidden from publishing) and
  Shape (sharp, default, round — the product's style first, so frames on Auto use it) collections, plus Color, Density,
  Responsive and the type styles its own text uses.
- Bind corners to `shape/*` variables (scoped to corner radius, so only the radius field offers them). Set a frame's
  **Shape** mode to see it in another style. Per-corner bindings (top-left …) work for joined parts and flush headers.
- Figma has no expressions: for a nested radius, type the value from the guide's table for the frame's modes.

## When something's missing

- **Another shape** (a thumbnail, a map marker) → add a role in the engine config (`radius.roles`): a name by job
  (`shape.<job>`) and a key on the scale per style (`"sharp": "1", "default": "3", "round": "4"`). The build refuses names
  by look or size, keys off the scale, radii that shrink from sharp to round and `full`, then computes its focus-ring radius.
- **A rounder or sharper product** → `radius.style`.
- **A new style or other values for the roles** → not in the config on purpose: the checks (order, corners, text inside)
  are built on them. Raise it as a design-system change.
