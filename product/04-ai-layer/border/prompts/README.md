# Border prompts

Four prompts for AI tools working with ds borders. Each is a ready-to-paste block with a short "what good looks like"
section, so the person using it can tell a good answer from a bad one.

| Prompt | Use it to | The AI must… |
|---|---|---|
| [Build with borders](build-with-borders.md) | build a screen | decide which boundaries need a line at all, give every line a job and a colour from that job, widen states with a second cue and compensated padding, keep every cue in forced colours |
| [Review borders](review-borders.md) | review code or a design before it ships | confirm the checker's and the audit's findings and find what tools can't: a line that space would do, a job chosen by look, a state shown by a fill the system can't see |
| [Add a border job](add-a-job.md) | handle "we need a thicker line for X" | look for an existing job first; if none fits, propose one in engine config the build can check |
| [Fit borders to a product](fit-borders.md) | choose the control width (and jobs) for a product | set up the config and run the engine; quote numbers only from its output |

## Always attach the rulebook

Every prompt expects `../border.md` — the border rulebook generated by the engine — in the same chat. It holds the rules
(BR-01 … BR-11), the decision guide, the jobs with their colours and measured contrast, the focus ring, the padding a state
gives up per density, joined parts, forced colours, the limits and the measured common mistakes. For tools that handle JSON
well, `../border.contract.json` has the same content.

Screens use colour, spacing, layout, radius and type too: attach those rulebooks as well when the work involves them.

Regenerate the rulebook whenever tokens change (`npm run build && npm run publish` in the engine folder).

## Trust, but check

- **Code** → `npm run lint:border -- <files>` reads the source; `npm run audit:border -- <page.html>` renders it at 1280 and
  320px and at 200% text, normally and in forced colours, and checks widths, control edges, seams, state changes, and that
  every control edge, state and focus ring survives forced colours.
- **New jobs and control widths** → `node src/cli.js <config.json> out/<name>`. The engine checks the jobs (B1–B6) and
  refuses unsafe ones.

See [../tests/](../tests/README.md) for how these prompts were tested and how to test them with your own tool.
