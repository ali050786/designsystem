# Spacing prompts

Four prompts for AI tools working with ds spacing. Each is a ready-to-paste block with a short "what good looks like"
section, so the person using it can tell a good answer from a bad one.

| Prompt | Use it to | The AI must… |
|---|---|---|
| [Build with spacing](build-with-space.md) | build a screen or component | plan every space by direction and relationship first, then write code with tokens only — no px, no primitives, controls as minimums |
| [Review spacing](review-space.md) | review code or a design before it ships | confirm the checker's and the audit's findings and find what tools can't: sizes chosen by value, groups that don't read as groups, markup that doesn't group what spacing groups |
| [Add a spacing token](add-a-space-token.md) | handle "we need a 20px gap here" | look for an existing token first; if none fits, propose one in engine config the build can compute and check |
| [Set the density](set-density.md) | choose how dense a product is | set up the config and run the engine; quote numbers only from its output |

## Always attach the rulebook

Every prompt expects `../spacing.md` — the spacing rulebook generated by the engine — in the same chat. It holds the rules
(SR-01 … SR-09), the decision guide, every token with its value in each density, the scale, the links to layout and the
measured common mistakes. For tools that handle JSON well, `../spacing.contract.json` has the same content in
machine-readable form.

Most screens use colour and type too: attach `../../color/color.md` and `../../typography/typography.md` as well when the work
involves them.

Regenerate the rulebook whenever tokens change (`npm run build && npm run publish` in the engine folder). An AI working from
an old rulebook will pick tokens that no longer exist.

## Trust, but check

An AI's answer is a draft. Each prompt names the tool that checks it:

- **Code** → `npm run lint:space -- <files>` reads the source; `npm run audit:space -- <page.html>` renders it in all three densities at desktop and 320px, measures every target and checks labels at 200% text.
- **New tokens and density settings** → `node src/cli.js <config.json> out/<name>`. The engine computes every density and runs every spacing check; it stops if one fails.

See [../tests/](../tests/README.md) for how these prompts were tested and how to test them with your own tool.
