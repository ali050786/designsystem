# Layout prompts

Four prompts for AI tools working with ds layout. Each is a ready-to-paste block with a short "what good looks like"
section, so the person using it can tell a good answer from a bad one.

| Prompt | Use it to | The AI must… |
|---|---|---|
| [Build with layout](build-with-layout.md) | build a screen | decide the frame first (which regions, which panes), then every width by job and every grid by spans — no px widths, no breakpoints of its own |
| [Review layout](review-layout.md) | review code or a design before it ships | confirm the checker's and the audit's findings and find what tools can't: a region doing the wrong job, text that isn't marked as text, visual order that contradicts the code |
| [Add a pane](add-a-pane.md) | handle "we need another sidebar" | look for an existing pane or width first; if none fits, propose one in engine config the build can add up and check |
| [Fit the layout to a product](fit-the-layout.md) | choose pane widths and tiles for a product | set up the config and run the engine; quote numbers only from its output |

## Always attach the rulebook

Every prompt expects `../layout.md` — the layout rulebook generated by the engine — in the same chat. It holds the rules
(LR-01 … LR-10), the decision guide, the breakpoints, every token, the classes, the shell at every breakpoint, the limits
and the measured common mistakes. For tools that handle JSON well, `../layout.contract.json` has the same content in
machine-readable form.

Screens use spacing, type and colour too: attach `../../spacing/spacing.md`, `../../typography/typography.md` and
`../../color/color.md` as well when the work involves them.

Regenerate the rulebook whenever tokens change (`npm run build && npm run publish` in the engine folder). An AI working from
an old rulebook will pick widths that no longer exist.

## Trust, but check

An AI's answer is a draft. Each prompt names the tool that checks it:

- **Code** → `npm run lint:layout -- <files>` reads the source; `npm run audit:layout -- <page.html>` renders it at every
  breakpoint's narrowest width and 1920px in every density, at 400% zoom and at 200% text, and tabs through it both ways.
- **New panes and widths** → `node src/cli.js <config.json> out/<name>`. The engine adds the panes up at every breakpoint and
  runs every layout check; it stops if one fails.

See [../tests/](../tests/README.md) for how these prompts were tested and how to test them with your own tool.
