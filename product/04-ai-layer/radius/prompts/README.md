# Radius prompts

Four prompts for AI tools working with ds radius. Each is a ready-to-paste block with a short "what good looks like"
section, so the person using it can tell a good answer from a bad one.

| Prompt | Use it to | The AI must… |
|---|---|---|
| [Build with radius](build-with-radius.md) | build a screen | give every shape a role by job first, then write corners as roles or nested expressions — no px, no pills on buttons, no clipping to round |
| [Review radius](review-radius.md) | review code or a design before it ships | confirm the checker's and the audit's findings and find what tools can't: a role chosen by size, a child that fills its parent without the nested radius, a ring drawn on its own layer |
| [Add a shape role](add-a-role.md) | handle "we need a radius for X" | look for an existing role first; if none fits, propose one in engine config the build can check |
| [Fit the radius to a product](fit-the-radius.md) | choose a style (and roles) for a product | set up the config and run the engine; quote numbers only from its output |

## Always attach the rulebook

Every prompt expects `../radius.md` — the radius rulebook generated by the engine — in the same chat. It holds the rules
(RR-01 … RR-10), the decision guide, the roles in every style, the nested-radius table, joined parts and focus rings, the
limits and the measured common mistakes. For tools that handle JSON well, `../radius.contract.json` has the same content.

Screens use spacing, layout, type and colour too: attach those rulebooks as well when the work involves them.

Regenerate the rulebook whenever tokens change (`npm run build && npm run publish` in the engine folder).

## Trust, but check

- **Code** → `npm run lint:radius -- <files>` reads the source; `npm run audit:radius -- <page.html>` renders it in all three
  styles at 1280 and 320px and at 200% text, checks nested corners, text outside its shape and joined groups in both text
  directions, and samples every focus ring on all four sides.
- **New roles and styles** → `node src/cli.js <config.json> out/<name>`. The engine checks the roles' order, corners, text
  and rings (R1–R4) and refuses unsafe roles.

See [../tests/](../tests/README.md) for how these prompts were tested and how to test them with your own tool.
