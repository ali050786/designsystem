# Motion prompts

Four prompts for AI tools working with ds motion. Each is a ready-to-paste block with a short "what good looks like"
section, so the person using it can tell a good answer from a bad one.

| Prompt | Use it to | The AI must… |
|---|---|---|
| [Build with motion](build-with-motion.md) | build a screen | decide what needs motion at all, give each moving part its job, let tokens.css open and close menus, toasts and dialogs, give every animation of its own a reduced path, write no durations or curves |
| [Review motion](review-motion.md) | review code or a design before it ships | confirm the checker's and the audit's findings and find what tools can't: motion nobody needs, the wrong job, attention-seeking loops, a reduced mode that hides the change |
| [Add a job](add-a-job.md) | handle "we need a special animation for this" | look for an existing job or ready transition first; if none fits, propose a product job the build computes |
| [Fix the motion](fix-the-motion.md) | clean up motion in existing code | replace numbers with jobs, take movement down to a job's distance, give every animation a reduced path, stop loops and flashes |

## Always attach the rulebook

Every prompt expects `../motion.md` — the motion rulebook generated by the engine — in the same chat. It holds the rules
(MR-01 … MR-10), the decision guide, the jobs with their full and reduced values, the curves, reduced motion, the ready
transitions, the loading indicator and highlights, the limits and the measured common mistakes. For tools that handle
JSON well, `../motion.contract.json` has the same content.

Screens use colour, border, spacing, layout, radius, elevation and type too: attach those rulebooks as well when the work
involves them. Menus, toasts and dialogs follow the elevation rulebook for how they open; motion only says how they move.

Regenerate the rulebook whenever tokens change (`npm run build && npm run publish` in the engine folder).

## Trust, but check

- **Code** → `npm run lint:motion -- <files>` reads the source (CSS, HTML, JSX); `npm run audit:motion -- <page.html>`
  renders it with full and reduced motion at 1280 and 320px, hovers every control, tabs through, opens every popover (and
  each `--open` selector; `--open "#a then #b"` clicks a chain), pauses every animation and steps it frame by frame to
  measure what really moves, which job it belongs to and how often it flashes.
- **New jobs** → `node src/cli.js <config.json> out/<name>`. The engine computes the durations and refuses durations,
  curves, names by look or speed, loops and anything further than 32px (M1–M4).

See [../tests/](../tests/README.md) for how these prompts were tested and how to test them with your own tool.
