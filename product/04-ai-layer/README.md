# AI layer

What AI tools need to use ds correctly: rules they can follow, data they can check against, and prompts people can paste.
Everything here is either generated by the engine or checked by it — nothing depends on an AI getting numbers right.

## How the pieces fit

1. **The engine** builds the tokens and runs every check (colour pairs in Light and Dark; type sizes, line heights and
   hierarchy at every breakpoint; spacing, targets and control fit in every density; grids, panes and the sticky header at the
   narrowest width of every breakpoint; radius roles, corners, text inside the corners and ring radii in every style; border widths, jobs kept apart, line colours at 3:1, states that don't move content, joined seams and forced colours; elevation levels, shadows growing with height, surfaces rising in Dark, edges seen against everything below and the stacking order; motion jobs, durations that follow distance, curves that never start at full speed, a reduced mode where nothing moves, loops and highlights that stay readable and ready transitions that use only tokens). From the same build it writes the
   rulebooks and contracts, so the rules always match what ships.
2. **People** paste a prompt from `color/prompts/`, `typography/prompts/`, `spacing/prompts/`, `layout/prompts/`, `radius/prompts/`, `border/prompts/`, `elevation/prompts/` or `motion/prompts/` into their AI tool, with the matching rulebook attached.
3. **Checkers** judge the result:
   - source: `npm run lint:color`, `npm run lint:type`, `npm run lint:space`, `npm run lint:layout`, `npm run lint:radius`, `npm run lint:border`, `npm run lint:elevation`, `npm run lint:motion`;
   - rendered page: `npm run audit:page` (colour, Light and Dark), `npm run audit:type` (type at desktop and 320px, with 200% text and the WCAG text-spacing override), `npm run audit:space` (targets, control heights and reflow in all three densities, labels at 200% text), `npm run audit:layout` (every breakpoint and density, 400% zoom, 200% text, focus under sticky bars, reading order, the drawer), `npm run audit:radius` (every radius style, nested corners, text outside its shape, joined groups both directions, every focus ring on four sides), `npm run audit:border` (1280 and 320px and 200% text, normally and in forced colours: widths, seams, states, control edges and a focus ring on every tab stop), `npm run audit:elevation` (Light, Dark and forced colours at 1280 and 320px: shadows, surface steps and edges measured against what is behind them, menus and dialogs opened, what is on top, clipped menus, dialogs that hold focus, focus under sticky bars), `npm run audit:motion` (full and reduced motion at 1280 and 320px: every animation paused and stepped frame by frame to measure how far it moves, whether it turns and which job its duration and curve belong to; flashes recorded in real time; hovers, focus rings, scrolling, menus, dialogs and toasts opened and closed);
   - the engine itself for new roles, styles, tokens, panes, shape roles, border jobs, layers, motion jobs, brands, fonts and densities.

## Keeping it current

In the `engine` folder: `npm run build && npm run publish`. That rebuilds everything and copies the guides, rulebooks,
contracts and demo tokens into place.
