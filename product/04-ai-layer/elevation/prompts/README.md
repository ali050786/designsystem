# Elevation prompts

Four prompts for AI tools working with ds elevation. Each is a ready-to-paste block with a short "what good looks like"
section, so the person using it can tell a good answer from a bad one.

| Prompt | Use it to | The AI must… |
|---|---|---|
| [Build with elevation](build-with-elevation.md) | build a screen | decide which parts need height at all, give each the level for its job, open menus as popovers and dialogs with `showModal()`, use no z-index numbers |
| [Review elevation](review-elevation.md) | review code or a design before it ships | confirm the checker's and the audit's findings and find what tools can't: height nobody needed, the wrong level for the job, stacking that works by luck |
| [Add a layer](add-a-layer.md) | handle "this has to go on top of everything" | look for an existing level, layer or popover first; if none fits, propose a product layer the build places |
| [Fix the stacking](fix-the-stacking.md) | untangle z-index races and clipped menus in existing code | move what opens over content to the top layer, give the rest layer tokens, remove the numbers |

## Always attach the rulebook

Every prompt expects `../elevation.md` — the elevation rulebook generated by the engine — in the same chat. It holds the
rules (ER-01 … ER-10), the decision guide, the levels with their surfaces, shadows and measured visibility, the stacking
order, the edges, Dark mode, modal dialogs, forced colours, the classes, the limits and the measured common mistakes.
For tools that handle JSON well, `../elevation.contract.json` has the same content.

Screens use colour, border, spacing, layout, radius and type too: attach those rulebooks as well when the work involves them.

Regenerate the rulebook whenever tokens change (`npm run build && npm run publish` in the engine folder).

## Trust, but check

- **Code** → `npm run lint:elevation -- <files>` reads the source (CSS, HTML, JSX); `npm run audit:elevation -- <page.html>`
  renders it in Light, Dark and forced colours at 1280 and 320px, measures shadows, surface steps and edges against what
  is really behind them, opens every popover (and each `--open` selector; `--open "#a then #b"` clicks a chain), checks
  what is on top, tabs through dialogs and checks that focus never hides under a sticky bar.
- **New layers** → `node src/cli.js <config.json> out/<name>`. The engine places the layer and refuses numbers, names by
  position and two layers in one spot (E6).

See [../tests/](../tests/README.md) for how these prompts were tested and how to test them with your own tool.
